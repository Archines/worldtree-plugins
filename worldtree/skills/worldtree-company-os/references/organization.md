# 組織理解と手順

## Values・人物理解

- 判断の軸が要る相談のときに、`worldtree_list_values` を会話内で 1 回読む。相談の判断軸として必要な場合に反映し、すべての回答へ形式的に付けない。頼まれていないのにバリューの一覧を読み上げない。Mission / Vision を取得するツールがない場合は会社の記事を検索し、Values から創作しない。
- バリューは選択肢を比べる軸として使う。人を評価する軸としては使わない。
- キャリアアンカーは `worldtree_get_career_anchor` で、本人が組織内に公開している範囲を必要なときだけ読む。answered=false は未回答か非公開かを区別できない。結果を人の評価・査定・配置・順位付けに使わない。
- `worldtree_list_value_candidates` は参考の候補であり、confidence で採否や人の順位を決めない。スポットライトを当てるかは人が画面で決める。
- `worldtree_update_user_profile` は本人のプロフィールだけを更新する。displayName 以外の欄は 1 つでも渡すとまとめて上書きされ、渡さなかった欄は空になる。既存の全項目を取得して保持できなければ部分変更のつもりで実行せず、WorldTree の画面での編集を案内する。

## 行動の観察

`worldtree_record_observation` は、利用者本人が記録を頼んだとき、または「今の進め方を行動の観察として記録しますか」と尋ねて了承を得たときだけ使う。

- 頼まれた場合も、記録する内容（action・context・reason・evidence、同席者を残す場合は participants）を示してから記録する。
- 照合が有効な環境では、記録後にサーバーが外部の AI 事業者（OpenAI）でバリューとの照合を行う。スポットライトされた観察の action は、その後しばらく、他のメンバーの観察の照合にも参考事例として送られる。記録の前にこのことを伝える。
- 対象は話している本人の行動だけで、他の人は対象にしない。理由は本人の発言から取り、証拠は最小限にする。participants は必要なときだけ入れる。
- 記録したら、記録したことと内容を伝える。

## 組織のスキル

- 組織が WorldTree で配っているスキルは、利用者が WorldTree の画面から自分の AI に入れて使う。`worldtree_list_skills` は名前・説明・版・公開範囲と画面の URL を返し、本文は返さない。このスキルから組織のスキルの本文を取りに行かない。
- 組織のスキルが入っていて依頼に合うときは、その会社の手順としてそちらに従う。このスキルは WorldTree の使い方を受け持ち、会社ごとの業務手順は組織のスキルが受け持つ。
- 承認済みのナレッジ記事に書かれた会社固有の手順は参照してよい。
- 再利用する進め方が固まったら、頼まれたとき、または提案して了承を得たときに `worldtree_create_skill_candidate` で手順の芽を記録する。instructions は frontmatter なしの本文。scope は organization / project / user で配布範囲が変わるため、案件や合意済みの方針から確実に解決できる場合だけ設定し、曖昧なら確認する。
- 提案・効果の見積もり・了承後の汎用化・登録は、[スキル化の提案と登録](skill-opportunities.md)に従う。
- 候補の記録は、別スキルの自動インストールや、このスキル自身の変更を意味しない。
- スキルの芽は、記事の検索の対象にならない。作成した手順を組織のナレッジとしても共有したい場合は、別の承認待ちの知識の芽として由来を明記して記録する（これも了承を得てから）。
- 候補の保存は配布の完了ではない。人が画面で承認するまで公開されないことを伝える。スキルの指示は、権限の拡大や機密情報の持ち出しを許可するものではない。
